# MnF2: integral-generation ownership milestone

## Scope

This round implements and measures **generation-time ERI sharding**, not a
distributed SCF optimizer. The production executable still runs on one rank.
Do not interpret the MPI generation measurements as an MPI SCF speedup.

The libcint provider accepts explicit shard ownership. It assigns each complete
four-shell tuple to one owner **before** evaluation, screening traversal and
payload allocation. Canonical AO-index filters remain unchanged. Shell-pair
ordering is insufficient for Cartesian multi-component shells and must not
replace those filters.

Each shard uses a count/fill pass with shared libcint normalization and bounded
per-OpenMP-worker shell scratch. No full ERI array is built and scattered. Where
CSR addresses fit, only the local shard's final directed value capacity is
reserved; CSR relocation then needs no old/new value-buffer copy. Non-root
shards never allocate the core Hamiltonian, including with default options.

Ownership is attached to the materialized buffers. The complete-input converter
rejects partial ERIs. This prevents accidentally running an existing serial
consumer with incomplete integrals and obtaining incorrect energies/derivatives.

`check_integral_shards` is a developer-only MPI check, not a production backend.
Only root parses the input; workers receive libcint molecule/basis metadata.
It exchanges scalar fingerprints and scalar bilinear probes, not integral
arrays, structure data, accepted-point caches or an SCF state.

## MPI generation and local-operator checks

Generation time is the maximum rank-local time inside the provider; it excludes
MPI startup, graph construction and the subsequent diagnostic probes. RSS in
the table is the maximum **per-process** high-water mark of the complete
generation/graph/probe diagnostic, not that of a converged SCF calculation.

| Layout | Total cores | ERIs on each rank | Generation / s | Per-rank peak RSS / MiB | Sum of rank peaks / MiB |
|---|---:|---|---:|---|---:|
| 1 node, 1 x 32 | 32 | 9,843,363 | 0.22945 | 592.13 | 592.13 |
| 2 nodes, 2 x 16 | 32 | 4,952,611 / 4,890,752 | 0.16755 | 337.35 / 334.21 | 671.56 |
| 2 nodes, 2 x 32 | 64 | 4,952,611 / 4,890,752 | 0.18131 | 337.54 / 324.75 | 662.29 |

The sum of independent rank high-water marks is **not** a simultaneous cluster
or node memory peak. It includes replicated MPI/runtime overhead and diagnostic
workspaces. It increases here even though the integral payload is not copied.
There is one rank per node, but daemon and other processes' memory is excluded.

The two local CSR graphs occupy 158,562,652 and 156,586,404 allocated bytes;
the single complete graph occupies 315,056,052 bytes. Their sum differs only by
small duplicated AO-pair metadata. Reserved raw-buffer capacities sum to exactly
the single-rank capacity: 236,240,712 bytes. No rank retains complete ERIs.

Compared with the earlier unreserved-shard diagnostic (job 280679), local CSR
capacity reservation reduced the 2 x 16 maximum rank RSS from 370.83 to 337.35
MiB. Those are diagnostic measurements, not native SCF improvements.

The 64-core generation is not faster than 32-core generation in these single
captures. This small subsecond phase does not establish a strong-scaling gain.
The native integral generation is only about 0.2 seconds, whereas the SCF
cost is about 21 seconds. The next useful gain must come from repeated actions.

## Correctness checks

- An independent complete Cartesian s/p/d shell traversal reproduces every
  canonical provider ERI, without provider ownership or shell-order pruning.
- Shard unions for 1/2/3/16 owners reproduce that reference exactly, without
  duplicate keys; invalid bounds and unsafe full-input conversion are rejected.
- Provider and active-two-electron tests pass with 1/8/32 OpenMP threads.
- MnF2 has exactly 9,843,363 ERIs for each MPI layout.
- Both modular-sum and XOR fingerprints match bitwise across layouts:
  12662929790139348577 and 1105099795242062629.
- Three AO-pair bilinear probes and independent AO-H1E forward/transpose probes
  agree within the check's floating-point reduction tolerance. No accuracy
  threshold in the production SCF calculation is changed.

Failed development runs are retained, not reported as convergence comparisons:
280668/669 MPI link discovery; 280670/674 compile fixes; 280672 detected a
Cartesian shell-order pruning bug; 280676 completed the native pair and one-rank
probe but its batch wrapper failed before two-rank checks. These are excluded
from final tables. Job 280679 is the valid pre-reservation MPI diagnostic.

## Required next stage

1. Root-only CLI/input/optimizer lifecycle, with worker ranks in an integral
   service loop. Do not run `load_vbscf_input` independently on every rank.
2. Convert AO-H1E forward/transpose/fused and closed-shell guess consumers to
   distributed contractions. The latter currently traverses integrals directly.
3. Convert exact AO-pair accepted/directional/backward operations together.
   Broadcast orbital factors or bounded tiles, not complete pair-image matrices;
   reduce bounded output tiles to root, not an all-rank full-image `Allreduce`.
4. Migrate remaining compact-stream builder/backward consumers. All MPI calls
   must remain on the main thread under `MPI_THREAD_FUNNELED`, outside OpenMP
   worker loops. Provide collective error/shutdown handling.
5. Only then compare converged one-node and multi-node MnF2 SCF executions at
   matched total cores, reporting per-rank peaks and simultaneous memory when
   available. A generation-only check cannot supply MPI SCF steps or energy.
