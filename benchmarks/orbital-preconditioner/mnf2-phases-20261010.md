# MnF2 parallel bottleneck: physical metric, not orbital HVP

## Measurement

Hanhai25 Slurm, exact/libcint, Davidson, NEO, gradient tolerance 1e-3,
energy tolerance 1e-7 Eh. No new iteration limit. OpenMP bound to cores;
BLAS uses one thread. Release -O3 with Eigen BLAS enabled. Starting revision:
d4b4c54. All build and numerical workloads ran on compute nodes.

Opt-in XMVB_PHASE_TIMING now covers NEO, HVP stages, structure solves and
adjoints, projected solves, orbital basis expansion, preconditioning, and
physical metric actions/dual norms. Counters occupy fixed-size storage. No
orbital, integral, or action images are retained by instrumentation.

Wall scopes and process CPU scopes are **inclusive**. In particular, the
projected solve includes physical dual-norm evaluation; basis expansion includes
HVP. Do not sum nested rows. CPU time includes OpenMP spin/wait time, not just
useful arithmetic. Short scopes have accounting/granularity error; their ratios
are not thread-utilization certificates.

## Diagnosis before optimization

Detailed native pair: job 280588, anode047, same input/executable and allocation.
Both runs converged in 14 steps, with 669 scalar HVP calls and 698 projected
solver iterations.

| Inclusive stage | 32-thread wall (s) | 8-thread wall (s) |
| --- | ---: | ---: |
| NEO solve | 130.90 | 150.02 |
| HVP apply | 21.27 | 41.55 |
| Physical metric / dual norms | 107.10 | 105.90 |
| Projected solve, including dual norms | 106.66 | 105.29 |
| Preconditioner | 0.21 | 0.20 |
| Structure response solve | 0.40 | 0.06 |
| Structure adjoint | 0.29 | 0.69 |

HVP average process CPU/wall was about 29.4 at 32 threads. The near-constant
metric time explains why increasing thread count barely helps the dominant
part of this calculation. The projected eigensolver and structure response
are not the primary culprit. Earlier coarse instrumentation missed this work.

HAO dual-norm evaluation repeatedly solves the reduced physical metric by CG.
Its matrix-free action performed per-active-orbital GEMV and rank-one updates,
streaming shared AO matrices repeatedly. This is separate from orbital HVP.

## Exact batching change

Compute all active-ray tangent columns together, apply the shared AO overlap
and projector using GEMM, perform the individual scalar ray projections, then
batch the active cotangent and inactive feedback contractions. This is an
algebraic regrouping of the existing metric action, not a change in metric,
gauge, solver precision, or convergence conditions. The full-CAS span branch
is unchanged.

Temporary storage is AO-by-active-orbital-sized, shared within the calling
scope. No per-worker AO matrix, integral tensor, or inverse metric is created;
no dense reduced metric is assembled. There is no added MPI replication.

## Regression

Physical metric/gauge/finite-map/Riesz-solve tests, coupled structure tests,
and shifted-metric preconditioner tests passed at 1, 8, and 32 threads.
Other systems ran concurrently as array 280593, with each baseline/update
pair serial on its own allocated node. Baseline here is d4b4c54, without the
new detailed instrumentation.

changes in these controls are not evidence of universal acceleration.

## Remaining priority

The physical metric still takes 54 seconds. Next investigate its repeated
inverse solves and mathematically appropriate structured preconditioning,
before changing orbital HVP threading or adding MPI ranks. The present change
reduces serial work; it does not establish efficient 32-core scaling of the
whole optimizer. Maintain the existing true-residual certificate.
