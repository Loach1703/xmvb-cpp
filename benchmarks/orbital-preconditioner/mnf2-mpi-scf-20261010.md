# MnF2: end-to-end integral-worker MPI

## What changed

This is the production continuation of the generation-only milestone in
`mnf2-mpi-20261010.md`. The optimizer is not replicated across ranks.

- Root alone reads the complete input and owns structures, selected-state
  caches, orbital coordinates, eigensolver and optimizer.
- Workers receive only libcint molecule/basis metadata, generate their own
  shell-quartet shard, and enter an integral-action service loop. No complete
  ERI array is generated for subsequent scatter.
- Exact AO-pair, AO-H1E forward, transpose and fused actions operate on local
  shards. Inputs are broadcast as bounded buffers; images are reduced to root,
  not replicated by an all-rank full-matrix Allreduce.
- Pair input/image tiles are at most 8 MiB each. The MnF2 maximum input tile is
  2,232,000 bytes. Workers do not receive the complete pair-column matrix.
- H1E forward/transpose private-image payload is capped at 32 MiB per operation
  by choosing the local OpenMP team size. This is not a bound on the whole
  session: it also retains integral storage and reusable transport workspaces.
- Forward, directional and uncached backward pair operations use the same
  CSR/SIMD row kernel. The redundant backward scatter with a full image per
  OpenMP thread has been removed. Compact-stream MPI pair actions use one local
  thread until a nonreplicating parallel scatter is available.
- Exactly one rank per node is required. MPI calls are FUNNELED through the
  main thread outside OpenMP regions. Collectives fail by MPI_Abort; root-side
  ordinary exit/error sends Stop so workers can finalize normally.

The optional build switch is `XMVB_ENABLE_MPI=ON`. OFF remains the default and
does not introduce a production MPI dependency. Numerical formulas, convergence
thresholds, optimizer parameters and SCF iteration limits are unchanged.

At equal total cores, 2 x 16 reduces application wall by **11.4%** against the
non-MPI control. 2 x 32 reduces it by **29.5%**, using twice as many cores.
All variants have 669 orbital HVPs, 688 pair actions, 669 fused H1E actions and
727 transpose H1E actions. Improvement is faster execution, not fewer steps.
Final energies differ by at most 6e-12 Eh. Small floating-point reduction-order
changes in ill-conditioned late iterations do not change the convergence step.

### Memory ownership, not a claimed global memory reduction

The two ranks own 4,952,611 and 4,890,752 unique ERIs, summing to 9,843,363.
Neither retains the complete integral payload. Root's graph has a dispatcher;
its local integral count is explicitly labelled as the root shard in output.

The sum of independent process high-water marks is 720.17 MiB for 2 x 16 and
755.59 MiB for 2 x 32, larger than the non-MPI control. These sums are **not**
simultaneous cluster peaks. One MPI rank per node reduces the application's
per-node process peak, but this does not include daemon/other-process memory.
The MPI single-rank executable also has higher RSS than the non-MPI control;
MPI/runtime allocation overhead has not been independently attributed. Do not
claim the whole program uses less aggregate memory.

## Current support boundaries and next work

This milestone supports the measured exact-integral resident-pair path with
read orbitals; it is not yet a universal distributed backend.

- RI, automatic closed-shell guess, sparse active-integral construction and
  generated-row contractions explicitly reject multi-rank execution. They do
  not quietly use root's partial graph or switch to full replicated integrals.
- AO-H1E density inputs must fit the 8 MiB transport bound; a single AO-pair
  column must also fit. Larger AO spaces need a true distributed row/factor
  interface, not a larger replicated-buffer threshold.
- Root still owns its full optimizer/structure/accepted-point matrices. The
  8 MiB bound applies to transported pair tiles, not all root matrices.
- Batch H1E currently dispatches columns individually. Fusing multiple RHS
  into one bounded integral sweep is remaining performance work.

The next useful extension is generated-row/factor transport: broadcast compact
orbital factors once, generate pair rows locally, and reduce bounded row tiles.
That removes unsupported large-pair consumers without forcing a complete
pair-coefficient replica on every rank. Distributing structure/CI state is a
separate task and must not be inferred from integral-worker MPI.
