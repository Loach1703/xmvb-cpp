# Exact-integral MPI: remaining consumer paths

## Implementation

This extends `1c61bd0` with the three previously unsupported exact consumers.
The RI implementation is unchanged.

1. **Generated accepted/directional rows.** Root broadcasts compact AO-by-active
   orbital factors and, when requested, direction factors. Each worker generates
   coefficient rows implicitly while contracting its local ERI graph. Accepted
   and directional images are computed in the same sweep, then reduced to root
   in row tiles. No complete AO-pair-by-active-pair transformation or image is
   broadcast. Existing accepted backward, fixed-adjoint HVP and outer-direction
   consumers now use this shared kernel without a second MPI-specific formula.
2. **Nonresident active-integral construction.** When the existing storage
   planner selects the nonresident path, root constructs coefficient row tiles,
   consumes reduced product rows and accumulates the packed active tensor.
   The final packed tensor remains root-only. Its contraction is column-tiled
   so a second full active-pair square matrix is not needed. Workers never
   construct the packed active tensor or the sparse active expansion.
3. **Automatic closed-shell guess.** Exact Fock construction shares the
   production AO-H1E operator and its distributed forward action. Root adds
   the core Hamiltonian once. The old separate eightfold ERI traversal and
   associated per-thread Fock images were removed. Its implicit density
   symmetrization is preserved, including nonsymmetric diagnostic inputs.

`generated_rows.cpp` owns local row generation/contraction. `mpi.cpp` only
owns transport, local dispatch and reduction. Native sparse construction is
retained as a distinct efficient contraction, not a fallback for MPI.

## Storage bounds and limitations

- Each transported factor buffer and each worker image tile is at most 8 MiB.
  Accepted/directional output tiles have separate bounds; this is not an
  8 MiB bound on the sum of all retained workspaces.
- Worker CSR target rows are disjoint across OpenMP threads: no full image per
  thread. Compact-stream row contraction makes one serial ERI traversal per
  tile, not one traversal per row. This branch prioritizes correctness/bounded
  memory and does not establish fast parallel compact-stream execution.
- Root owns the final packed active tensor, structure/optimizer state and the
  caller's requested result rows. These remain existing root-side memory
  requirements, not distributed objects.
- Native sparse construction retains its support-sparse arithmetic. Small
  thread-private packed images share a 32 MiB budget; when the image itself is
  larger, one accumulator is moved into the result without a second full copy.
  This bounds replication but is not a claim of parallel large-tensor scaling.
- AO-H1E density buffers and AO-by-active factor buffers larger than 8 MiB
  remain explicitly unsupported by this MPI transport. A single active-pair
  output row must also fit. They are rejected, not expanded into unbounded
  rank replicas. These limits must not be described as universal large-AO MPI.
- The full root ERI reference and wide images in `check_integral_service` are
  restricted diagnostic fixtures, not production allocations. Production
  workers generate only their shell-quartet shard.

## Sparse-construction correctness repair

The new independent dense-factor test exposed two related symmetry omissions
in the old nonresident sparse forward contraction:

- An off-diagonal AO pair mapped to a diagonal active pair needs both orbital
  product orientations; the sparse coefficient row previously retained one.
- An off-diagonal AO operator edge contributes through both orientations to
  a diagonal active tensor element; the packed contraction previously retained
  one.

Both terms are now accounted for. This is a mathematical symmetry repair, not
a tolerance or convergence adjustment. A small regression with one AO edge
and two mixed AO coefficients has analytically known active diagonal 8; the
old implementation produced 2. The full random mixed-factor test independently
compares every packed entry with the complete symmetric pair operator.
Resident MnF2 did not use the defective sparse forward branch.

MnF2: equal-total-core 2 x 16 reduces application wall by 15.4%; 2 x 32

F2-auto: all have 5 steps and 11 HVPs with identical printed final energies.
The application is too small for a useful end-to-end MPI speed claim. GNU
elapsed, including MPI startup/finalization, is 0.14 s for non-MPI, 0.55 s for
MPI 1 x 32, 0.50 s for 2 x 16 and 0.53 s for 2 x 32. MPI is slower for this
whole-process workload despite the shorter application timer of 2 x 16.

The sum of independent rank peaks is 726.95 MiB for MnF2 2 x 16 and 757.91 MiB
for 2 x 32, higher than the non-MPI baseline. It is not a simultaneous cluster
peak. Integral sharding lowers each node's application-process memory, not
necessarily aggregate RSS after MPI/runtime overhead. No process peak includes
other node processes or daemons. No complete integral or large active tensor
was copied to workers to obtain these timings.

The final native sparse private-image memory guard was added after this capture
and verified separately. It does not affect these resident SCF paths or the MPI
nonresident implementation; the captured executables are preserved unchanged.
