# Shared-input AO-pair SIMD and distributed-ownership audit

Baseline 9dc5ba8; NEO, Davidson, exact/libcint, gradient/energy criteria
1e-3 / 1e-7 Eh. Compilation, tests, native measurements, gprofng and vector
diagnostics ran only in Hanhai25 Slurm compute jobs. No numerical threshold,
iteration budget or integral approximation changed.

## Retained change

Separate the row-owned CSR contraction from OpenMP team orchestration. A single
C++ implementation is compiled into default, AVX2 and AVX-512 variants on
GCC/x86-64; runtime ISA dispatch follows [GCC function multiversioning](https://gcc.gnu.org/onlinedocs/gcc/Function-Multiversioning.html).
Other builds compile that same source with their baseline vectorization.
This is hardware dispatch, not a retained obsolete numerical algorithm.

Each worker contracts a disjoint contiguous row range. CSR metadata, integral
values and source coefficients are shared read-only; only the owned result
rows are written. There is no new heap workspace, integral cache, per-worker
matrix, global stencil table, architecture-specific data layout, or global
`-march=native` requirement. CSR edge summation order is unchanged in source;
ISA-dependent floating-point code generation can change last-bit results.
The arithmetic scaling remains edges times active-pair width. This is a SIMD
constant-factor improvement, not a lower-complexity contraction algorithm.

## Rejected contraction order

Job 280643 used eight-column register blocks, traversing the complete CSR row
again for each block to write each result element only once. It has no large
private buffers but increases index/value traversal by ceil(width/8). Native
MnF2 wall rose 24.69 -> 35.94 s and AO-pair time 6.5383 -> 18.2258 s. The code
was deleted; no selector, switch or fallback for it remains. Reducing output
writes alone was not enough to offset repeated graph/source traversal.

## Correctness and compilation evidence

Physical-map, quotient, inverse-metric, coupled-structure, shifted-preconditioner
and exact two-electron tests passed at 1/8/32 threads in job 280652. Additional
lane-tail tests compare the CSR action with an independent dense operator for
widths 0, 1, 2, 3, 4, 7, 8, 15, 16, 31, 32, 36, 64 and 65 and start from poisoned
output buffers. An empty-width return avoids pointer arithmetic on empty maps.
Final lane tests and rebuild are in job 280663.

The diagnostic recompilation in job 280654 confirms 16-, 32- and 64-byte
vectorization for the row kernel. Its object is not linked into native runs.
The exact sampled binary and gprofng experiment are preserved. Resolved row
contraction and AO-H1E functions remain qualitative hotspots. The collector
again reports a changed interval timer; sample percentages are not accepted
as precise CPU shares or wall-time costs.

## Algorithmic and MPI findings

The shifted orbital preconditioner already applies the complete model
P + lambda G inside its PCG solve. P + lambda I is only the inner block
preconditioner; treating it as the true shifted model would be an incorrect
diagnosis. Its measured cost is small compared with HVP kernels, so no
unmeasured residual relaxation or further heuristic was introduced.

MPI is **not implemented or benchmarked by this change**. Launching multiple
copies of the existing driver would independently build complete AO integrals,
pair maps and accepted-point objects and would violate the memory goal.
The required ownership sequence is:

1. Generate/retain disjoint AO-integral or CSR-row payloads per node, before
   large storage is allocated. Keep a single orchestration/optimizer state.
2. Use one MPI rank per node and OpenMP/SIMD within the node initially, avoiding
   intra-node replicas of immutable inputs and workspaces.
3. Communicate orbital factors and bounded source-row tiles/halos required by
   local rows, not full per-rank AO-pair-by-active-pair matrices. Dense CSR
   connectivity can make halos effectively global; that cost must be measured,
   not assumed negligible.
4. Reduce only contracted active-space images or owned output tiles. Include
   communication and maximum simultaneous node memory in the benchmark.

The row kernel now has explicit disjoint range ownership, but that alone does
not provide distributed input construction. No unused MPI shim, duplicated
driver, or toy MPI backend is added to production code. Reducing AO-H1E stream
decoding/scatter cost and diagnosing actual worker imbalance remain next
single-node targets; cross-node scaling requires the ownership work above.
